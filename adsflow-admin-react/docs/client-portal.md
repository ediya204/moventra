# 客户端首期实现

入口 `/portal`。使用 `npm run dev` 启动，与管理端共享 MUI 主题，独立懒加载。当前版本是可交互的合成数据演示，不是可上线的客户金融服务。

资金中心已扩展为 USDT/USD 完整演示流程，最新范围、演示参数和验收路径见 [客户资金中心](client-finance.md)。

## 已完成

- 独立演示入口、工作台与八项导航；窄屏抽屉导航。
- 资金概览、充值申请与处理中流水；申请不增加余额。
- 零余额模拟开卡、卡片详情、账户向卡片充值、自助冻结解冻、风控冻结问题反馈。
- 交易查询、状态筛选、详情、当前筛选 CSV 导出、关联工单。
- 子账户创建、成员邀请待接受记录、角色选择、消息已读。
- 开户名称与邮箱提交、待审核状态、支持问题记录、退出清空。

## 数据与边界

`src/portal/model.ts` 为纯状态转换；金额以整数美分处理。转卡同步扣账户与增卡余额，拒绝负数、小数美分、余额不足和冻结卡。数据仅存在页面内存，刷新与退出重置，不调用 `/admin-api`，不发送邮件。演示角色固定为管理员，所选成员角色仅为展示配置。开卡为立即生成的模拟卡，真实渠道必须异步办理。种子余额为期初快照，不由三笔示例交易推导。

开户演示独立于预置的已开通组织；提交资料不会模拟审核或服务开通。兑换与提现已有合成数据演示；真实密码、二次验证、卡敏感信息、金融渠道、预算及批量操作尚未接入。

## 后端接入要求

需要提供客户专用认证与 API，服务端从会话确定组织、成员及授权范围；不可依赖隐藏按钮或用户传入的账户编号。开卡、充值、划拨必须有服务端幂等和原子账务处理、异步渠道结果及查询接口。账户审核、服务开通、资金到账分离。金额、币种、费用、状态和可执行操作由服务端验证和返回。

接入前还需完成真实开户字段及附件规范、费率与币种、角色权限矩阵、子账户资金归属、客户卡资料展示方式和业务验收用例。演示入口不能作为真实身份认证。

## 验证

- `npm run build`：TypeScript + Vite 生产构建。
- `node --test tests/portal-model.test.mjs tests/portal-finance.test.mjs`：Node 22.18+ 原生 TypeScript 支持；验证余额守恒、待处理不入账、冻结约束、金额精度与重复数据。
- 浏览器已检查入口、工作台，以及 100 USD 充值申请后可用余额不变且处理中增加。

## 2026-09-07 正式客户端首页

正式客户端新增 ClientHome：通过身份与本地账户校验后，/session 自动进入 /portal。提供首页、我的账户、交易记录和账户与安全（/portal/security）；未注册、停用、未验证及服务异常保留原身份处理。运营域名入口不变。

仅按服务端授权主体读取真实账户/交易；数量标注最多前50条，不冒充总量。未关联、加载、失败和空数据分别展示；没有假余额、卡片或交易。切换主体丢弃旧请求结果。日期按浏览器本地时区，金额按字符串最小单位显示。原模拟 Portal 仅用于开发 Demo。

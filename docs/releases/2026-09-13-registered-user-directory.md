# 正式注册用户目录修复

2026-09-13。问题：正式客户端能登录的用户无法在后台按邮箱找到。旧“用户与开户”入口被替换为开户审批，账户目录只读取已授权客户账户，没有登录用户查询链路。

## 范围与授权

用户明确选择“所有后台管理员都可以查看”注册用户基础资料。新增独立注册目录只读权限规则：active admin + 已验证 MFA；包括尚未关联客户的注册用户。客户账户、交易及审批继续按原 staff_grants，每次业务请求独立校验。没有自动授权、开户、服务激活或金融写操作。

- 正式 `/user-groups/users` 恢复为注册用户目录，顶部邮箱搜索转入此页；开户审批、账户目录保持独立。
- `GET /admin-api/v1/users` 默认分页列出正式 customer 用户；完整邮箱精确查询通过 Firebase 获取 UID，再关联正式注册资料。查询也能识别“仅创建身份、尚未注册”。
- 展示邮箱验证、登录身份状态、注册状态、客户关联状态；缺业务授权仅显示关联存在，不暴露客户名称、ID 或操作链接。
- 身份服务失败返回 503，身份确实不存在、尚未关联、不具备业务权限分别显示。查询不复制 Firebase 密码、令牌或 provider 原始资料。
- 新增 005_user_directory_audit，仅创建查询审计表及索引。所有成功读取（含空结果）必须提交审计后返回；迁移不改旧表、用户角色或权限。就绪检查要求 005。
- 旧 ADSFLOW 目录及本地演示数据库保持原样，没有将 Demo 客户迁入线上。

# 卡片当前状态同步

## FLOW-CARD-SYNC-01 · 2026-09-18

用户确认实施卡片同步。基线 60d3295，main；保留并行资金与文档改动。遵循[开发总纲](../DEVELOPMENT.md)、[业务闭环标准](delivery-standard.md)、[资金规则](../domain/transactions-and-funds.md)及[Slash 接入](../integrations/slash.md)。

起点：Slash 卡片通知、每五分钟补查、用户手动请求；终点：客户端“我的卡片 → 详情”和运营“全部卡片 → 详情”读取同一已核验状态。卡片状态由渠道 GET 权威返回；内部归属仍由 project_wallet_cards 决定，同步不能分配卡片。事件记录和旧导入保持不可变，新增当前状态读模型；固定历史测试快照维持原语义。

接口链：签名校验 → 持久化通知 → 后台回查账户及卡片 → 校验连接/账户/钱包/卡片 → 原子记录观察与发布状态。定时任务仅补查已正式归属的卡；手动 POST 复用客户所有权或运营 MFA + 渠道授权，异步返回202，页面轮询读取结果。返回 pending/synced/stale/error 与 checkedAt；失败保留最后核验值，绝不伪装成功。重复、乱序通知均重新 GET 当前卡片，串行工作锁防止旧 HTTP 结果覆盖新结果；404 标记待核实，不推断销卡。

本批仅卡片生命周期状态同步，不新增冻结/解冻命令、CVV、额度修改、消费利用额或资金记账；这些仍需各自业务闭环。未来渠道可写相同 current model，Slash 事件与回查位于适配层。交易流水仍保持原导入语义，页面分别说明。

验收：正常更新、重复与乱序、失败恢复、账户/钱包错配、跨客户越权、状态筛选一致、历史快照不变、前后台刷新。先本地自动化，再真实只读核验与部署，阶段独立记录。

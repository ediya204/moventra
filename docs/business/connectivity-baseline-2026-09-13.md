## 3. 整改顺序

| 批次/流程 | 完整目标 | 依赖及本轮状态 |
| --- | --- | --- |
| B0 基线收敛 | 核准仓库/提交/工作区 → 对照文档 → 列明逐项迁入范围 | 最高优先级，Git 状态及差异原因待确认；不覆盖已有工作 |
| B1 / FLOW-001 个人交易只读 | 客户交易列表 → 交易详情 → 所属账户 → 返回；获授权运营查询同一客户投影并核对 ID/金额/状态 | 首选实施链；基线确认后补正式详情契约、分页、运营入口及 E01–E06/E08；不导入新生产数据，不做客户与未归属渠道投影混接 |
| B2 / FLOW-002 渠道调查只读 | 后台来源交易 → 精确详情 → 同连接卡片 → 返回筛选与页码 | GAP-01/02 先解决；保持连接授权和 MFA；无客户映射时仅后台，不以“前后台联通”为由开放客户读取 |
| B3 / FLOW-003 客户申请与运营处理 | 客户申请 → 后台待办 → 申请及关联对象详情 → 处理 → 客户结果及双方审计 | 选择隔离卡解冻申请为候选；先确认受管卡归属、角色及复核规则，真实渠道执行不在本批默认范围 |
| B4 资金及对账 | 每种订单分别形成跨端闭环，再对接有证据的分录和差异处理 | 依赖原有领域规则、期初/权威账本/政策确认；不能将原型余额视为正式可用资金 |
| B5 配套模块 | BIN/费率/消息/工单/系统配置按具体业务关联补齐 | 各模块仍需独立流程卡；消息派生自真实业务事件，不能伪造通知证明处理成功 |

B1 最小验收夹具：隔离客户 A/B、获授权运营与未授权运营、A 的超过 50 条 USD/USDT 查询投影。校验分页边界记录、复制详情链接、跨主体换 ID、两端相同记录一致以及服务异常。金额仅使用测试投影，不增加真实资金。具体路由和详情 DTO 待基线确认后设计，不把本表作为已存在接口。

负责人：后续当前开发任务承担调查、流程卡和实现验证；业务/财务政策确认人待分配。B0 阻塞代码迁移基线，金融政策阻塞对应写流程，不阻塞规范整理或已获授权的只读调查。

# FLOW-CARD-DETAIL-02：客户端卡片详情规划

日期：2026-09-18。状态：DESIGN，用户请求规划，未授权本轮业务实现、部署、敏感信息实际查询或真实资金操作。此前后台归属修复保持独立，未因本规划获得发布授权。

## 1. 基线与目标

- 项目：Moventra。远端本地引用 origin/main 812e5ae 与共享目录当前开发文件分别核对，不把共享目录中的未发布能力算作线上能力。
- `apps/client/src/portal/CardSnapshots.tsx` 已有列表、`/portal/cards/:id?connection=...`、关联交易及交易详情抽屉；当前仍是已导入记录查询，无完整卡资金操作工作台。
- 正式已有 customer_card_bindings 与 project_wallet_cards；客户归属不得根据卡名、尾号或 Slash cardholder 推断。
- 本地 issuing 已有订单/首充及特定失败恢复 topup，不能当成任意已发卡的常规充值或提现闭环。现有影子/测试余额不能升级为生产可用余额。
- 目标：卡片中心 → 单卡详情 → 卡信息、交易、充值/转出记录与逐笔详情 → 返回原列表，刷新/深链后保持同一卡身份和筛选。

## 2. 页面结构

保留现有详情 URL，增加 `tab=overview|transactions|funding|activity`。列表点击卡名或“查看详情”进入独立页面；逐笔交易、资金订单用可恢复 URL 的抽屉显示，移动端全屏。连接、页码、筛选、排序和返回上下文保留，切换卡片清除上一卡请求结果及敏感数据。

顶部显示内部卡片名称、品牌、尾号、渠道状态及数据更新时间。内部名称按已经确认的随机姓名规则生成并持久化，不在刷新时重抽，不表示持卡人身份；Slash 默认 cardholder 不展示。支持能力明确时才出现对应操作。

| 标签 | 信息 | 交互 |
| --- | --- | --- |
| 卡片信息 | 卡名、掩码卡号、品牌/BIN产品、币种、有效期（来源可用时）、开卡时间、来源状态；已核验的账面余额、预占、可用余额、可转出余额；消费限额另列 | 按需查看卡号/CVV；充值、转出到钱包；冻结/解冻留后续阶段 |
| 交易历史 | 商户、消费/退款/费用/撤销类型、原币与账户金额、授权时间、入账时间、独立交易状态 | 服务端分页；类型/状态/日期筛选；逐笔详情、真实退款关联及拒绝原因（有依据才显示） |
| 充值与转出 | 充值、退回钱包、相关手续费、冲正；订单号、金额、净到账、币种、申请/完成时间、状态 | 类型/状态/日期筛选；详情中查看钱包与卡分户方向、处理时间线、失败原因、可用恢复动作 |
| 操作记录 | 开卡、查看敏感资料、卡片状态/名称/限额变更等客户可见事件 | 显示时间、动作、结果；不暴露内部风控备注、凭据或敏感原文 |

缺少数据来源的余额显示“暂不可用”，不能显示 0。已接入但确实无资金订单时显示“暂无记录”；未接通资金记录接口则显示“记录尚未接入”，不能用空数组冒充无记录。来源时间和查询时间区分，过期或部分覆盖明确提示。

列表当前硬编码的“测试快照”提示应按 API syncMode/coverageReason 与实际能力显示：项目钱包逐卡投影、固定测试快照、真实资金能力分别表达，不能仅换文案就声称资金已接入。

## 3. CVV / PAN 按需展示

用户约束：CVV 不在本地保留，通过本系统服务端向上游查询。完整 PAN 采用同样的不持久化原则；常规列表、导入、Webhook、导出只保留内部 ID、渠道 ID、尾号等允许字段。

官方依据（2026-09-18 核对）：https://docs.slash.com/api-reference/card-get-by-id 。页面明确要求敏感数据查询使用 `https://vault.slash.com/card/{cardId}`，选择 `include_pan=true` 和/或 `include_cvv=true`。CVV 字段描述仍含 include_pan 的旧表述，与页面请求说明不完全一致；实施联调验证独立参数实际行为，不能为“只看CVV”无意扩大请求范围。文档可查询不代表当前租户已经开通或实测成功。未发现已确认适用于本租户的 Slash 托管 iframe，不能把其他渠道 iframe 能力当成 Slash 已支持。

设计流程：

1. 默认只显示掩码；用户明确点击“查看卡号/CVV”，不随页面打开、列表刷新或悬停预取。
2. 服务端检查有效身份、本人客户主体、连接/cardId 实际归属及独立 reveal 能力。仅有测试数据查看绑定不自动授予敏感数据查看权，需确认这些已导入卡的真实使用授权。
3. 使用近期重新认证/MFA，建议认证窗口 5 分钟；签发仅绑定当前用户/会话/卡片/字段的短时一次性 reveal 授权。该窗口及展示时长为产品建议，不是 Slash 官方限制。
4. 固定服务端上游地址、实体和凭据，拒绝前端自报上游 URL/accountId/cardholder；通过受控出口向 Vault 查询。只返回明确请求且经验证的字段。
5. 建议显示 30 秒；超时、隐藏标签页、切换卡片、退出登录或关闭详情时立即遮罩并移除当前组件持有值。正在进行的请求取消或丢弃迟到响应，不能在退出后重新显示。
6. 服务端只在请求处理内短时使用，不落库、不进入 Redis/任务队列/来源快照/磁盘/备份；反向代理、Cloudflare、APM、错误上报、trace 和响应体日志全部排除敏感载荷。
7. 前端仅当前组件临时内存使用，不进 localStorage/sessionStorage/IndexedDB、持久化状态、Service Worker 或查询缓存；请求/响应 `Cache-Control: no-store`，网关及 CDN 绕过缓存，页面不使用会话回放采集该区域。
8. 审计只保存谁在何时查看哪张卡、查看了哪些字段、是否成功及请求关联号；不保存 CVV/PAN、认证凭据或返回密文。查询失败显示失败，不回退到旧明文。

默认不提供 CVV 复制/导出。若后续要求复制，单独设计剪贴板持久性与交互。内存移除和自动遮罩不能保证操作系统、浏览器扩展或用户截图没有副本，不声称“无法截屏”或“零安全合规范围”。上游密钥始终留在服务端。

## 4. 资金含义与状态

本规划将卡内“提现”定义为“转出到本人钱包”，避免用户误以为直接转到银行卡或链上地址。对外提现是资金中心另一条业务流程，不包含在单卡第一版范围。此定义是待用户确认的产品假设。

- 充值：本人钱包 → 本卡内部资金分户；平台上游资金池补款是另一个过程。
- 转出：本卡可转出金额 → 本人钱包；不将卡片消费限额或 Slash utilization 当成真实可转出资金。
- 消费退款保留在交易历史，不能标成用户发起的转出；转账失败释放预占也不能重复记为新充值。
- 每笔资金订单关联客户、连接、内部卡、账本操作、币种/精度及独立手续费；内部与渠道执行状态分开，卡分户出入两端原子或可恢复，金额精确。
- 展示状态：处理中、待核实、成功、失败、已取消；内部可细分预占/待执行/渠道确认/入账。成功需所有必要渠道步骤和账本事实完成，不用 HTTP 200、审批通过或单独调限额代表成功。
- 金融重试复用幂等键；超时先查原订单。未知结果不二次发起、不自动释放；失败仅在结果确定后释放或冲正，保留原记录。
- pending 授权、未清算交易、来源延迟可能影响可转出值。卡资金映射、占款覆盖、消费执行控制、费用规则及真实账本尚未验收时，允许展示已有真实记录，保持资金按钮不可执行并说明原因。

## 5. 拟议接口与存储边界

以下为新设计示意，实施时复用现有端点/DTO，不静默替换 card-projections 和 issuing 契约。卡身份以内部稳定 ID 映射 connection/resource/external ID；第一阶段旧深链保持可用。

| 接口职责 | 设计 |
| --- | --- |
| 基础详情 | 现有 card-projections 卡详情扩展脱敏来源字段；组装实际能力、资金数据来源及更新时间；不可返回 PAN/CVV |
| 交易查询 | 复用已有按 customer/connection/cardId 查询，保留授权范围、固定版本与分页；补筛选和明细字段白名单 |
| 卡资金记录 | 新增按内部卡过滤的资金订单列表/详情；归并已有开卡首充、后续充值、转出及手续费，避免首充重复显示/记账 |
| 操作记录 | 客户可见审计投影；过滤内部备注及敏感负载 |
| 敏感展示 | 独立 POST reveal，不放入普通 GET 卡详情；通过既有同域网关的精确路径放行、重新认证与逐卡授权、受控 Vault 适配器 |
| 充值/转出执行 | 后续独立幂等 POST 命令及 GET 订单状态；既有失败恢复 topup 不能无审查地扩展到正常卡 |

卡片基本映射、真实资金订单及非敏感审计可持久化；CVV/PAN 不进入任何表。不得迁入旧 Demo 假余额，历史未建卡分户先设计受控映射与期初证据，不补造充值流水。

## 6. 实施次序与验收

第一批：在现有详情路由实现顶部信息和四个标签，联通已有卡资料/交易，按能力显示余额与记录可用性，修正硬编码测试提示；不增加资金执行。

第二批：独立敏感展示链路，先合成数据验证越权、MFA、超时、自动遮罩、迟到响应、缓存与日志排除；再经明确授权核对真实 Vault 支持及对应卡片使用权。以无敏感值的验收证据记录结果。

第三批：真实内部资金记录统一查询、逐笔详情及对账关系；若生产资金账本未就绪，仅展示可核实记录，避免界面“看似已开通”。

第四批：完成钱包/卡分户、授权占款和渠道执行验收后，开放充值与转出；冻结/解冻、限额管理另批接入。

验收覆盖：
- E01–E04：列表→详情→交易/资金单→返回；复制深链/刷新、页码和标签还原；前后台读取相同归属和同一资金事项。
- E05：换客户/cardId/连接或伪造父子关系拒绝；仅有测试快照权限不能 reveal；运营与客户敏感权限分开。
- E06：断网、503、429、过期身份、上游拒绝单独提示；失败不显示“无记录”、0 或旧 CVV。
- E07：重复点击、并发充值转出、超时重试、通知乱序不重复影响资金；旧卡迟到结果不覆盖新卡。
- E08：服务端分页、筛选和覆盖范围一致；记录各自时间口径，不能声称已查全所有历史。
- E09：金额、预占、费用、退款与转出区分；查看敏感信息前后扫描合成测试日志/缓存，确保无载荷保留；审计失败阻断展示。

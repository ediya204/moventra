## 最新产品决定

### 资金流与运营概览

正式 `/workbench` 在运营身份和 MFA 通过后开放；`/session?security=1` 保留身份与安全设置。Go 按该运营已有的逐客户 `transactions:read` 范围汇总 USD，支持最近 7/14/30 个香港自然日；`succeeded` 进入流入/流出，pending/failed 仅计笔数。新增渠道投影未接入此聚合，概览中的卡片/商户运营指标仍为不可用，不因渠道明细可读而自动补齐。

DEV 管理总览使用已保存的 Slash 投影绘制资金流、交易活跃度、状态分布及消费商户排行，并与本地开户/用户/费率待办分区展示。收支按来源 posted，商户排行另限已入账且 settled 的卡消费；不等于收入、利润、可用余额或全量结算。无来源日期金额留空。

打开页面、切换周期或刷新时重算已入库数据；刷新图表不触发上游同步。图表按香港日分桶，卡交易列表按 UTC 日筛选，不能不换算边界就逐日比较。见 [概览口径](frontend/operations-overview.md) 和 [Go 汇总契约](../services/api/docs/operations-overview.md)。

### 个人账户与费率

V1 移除面向客户的团队协作入口。底层主体隔离、账户归属及后台内部角色权限保留。独立用户组入口已归并到 `/pricing`；方案维护为 `/pricing/plans` 和 `/pricing/plans/:id`。沿用内部 group_id 及用户覆盖 → 方案默认 → 系统默认的继承关系，不把费率方案当作团队。

### 卡片、用户与 BIN

DEV 卡片列表默认展示卡片名称、后四位、来源状态、创建时间、内部所属用户、渠道；本地额外工作台将操作列放在最后。渠道状态保留原值；未知值明确提示。正式只读卡资料没有内部绑定或管理操作。

本地所属用户读取内部用户数据库；卡片绑定按命名空间、平台、连接和卡片 ID 隔离。未绑定不从卡名、商户、渠道账户名推断归属。本地交易展示当前卡片归属，不代表历史交易归属快照或客户资金授权；该 Demo 绑定不随白名单导入正式渠道投影。

卡 BIN 维护详情首屏显示状态区域、影响说明和保存操作。状态包括草稿、上架、暂停、归档，使用既有保存 API 和版本校验；归档不可恢复。已核验的 Slash 产品目录与本地开卡政策分开；真实发卡未接入。

### 卡交易流水

正式 `/transactions` 从独立获授权连接查询卡交易，每页 20 条，支持商户/尾号/ID、详细状态、UTC 来源日期筛选；查看详情再读精确交易与卡资料。列表带导入版本并检查变化，单笔详情读取当前版本。`/cards/:id?connection=...` 仅显示基础来源资料、未绑定及资金操作未接入提示。没有金额汇总，也不开放 DEV 卡片管理。

DEV `/transactions?source=slash` 固定查询有来源 cardId 的交易。两种页面共用以下 detailedStatus 展示分类：

| 值 | 展示 | 颜色 |
| --- | --- | --- |
| pending | 待入账 | 橙色 |
| settled | 已结算 | 绿色 |
| declined | 已拒绝 | 红色 |
| reversed | 已撤销 | 蓝色 |
| refund | 退款 | 蓝色 |
| dispute | 争议中 | 红色 |

入账状态 status 仍独立保存。其他原始枚举不删除、不转成成功；该页面不提供 ACH 等通用资金分类。卡关联筛选先于分页和汇总；无卡关联的账户收支不混入卡交易。cardId 是关联证据，不据此伪造来源 category。

列表以商户、卡片、原币金额、账户金额、状态、授权时间和入账时间为主要列。`0d5158d` 已上传商户标识，正式列表有“查看详情”操作；DEV 列表仍可点击行打开抽屉。Logo 来自名称匹配，只是显示辅助。抽屉包含商户描述/MCC、单行地区、来源日期、金额和关联卡；内部用户只有本地已绑定时可用，原始调查字段收进折叠区。

“所属卡片”展示来源卡名与有效四位尾号。已上传 DEV 从精确来源 ID 打开 `/cards?source=slash&detail=<cardId>` 弹窗；规范工作区改为 `/cards/:cardId?source=slash` 五标签独立页，该增量未合入。它与正式 `/cards/:id?connection=...` 基础资料页不同。固定卡目录外的关联卡可读本地缓存，不加入固定选定集合；正式导入可包含这些关联卡，其数量不等于选定 40 张。缺失名称/尾号提示未采集，不用 ID 后缀替代卡号。

DEV 时间范围支持最近 7/14/30 天及自定义 UTC 日期，默认 30 天、结束日含全天、自定义最多 30 天；列表、总数和 posted 汇总共用来源 `date` 范围。非法/反向/未来日期不发请求。正式页面使用另一套起止日期：开始含、截止不含，默认不限日期，可只填一端，未设置 DEV 的 30 天限制。两端历史查询均只读已保存记录；不要混用日期控件说明。见 [DEV 日期筛选](frontend/transaction-date-range.md) 和 [正式契约](business/routes-and-api.md)。

### 同步与金额

真实 Slash 同步暂为手动。启动、打开页面、时间流逝均不触发上游请求；界面仅定期读取本地状态。手动关联卡补采为独立只读操作，不改变交易、余额或全量同步成功时间。Webhook 的接收、验签、幂等与乱序处理留待正式接入。

正式渠道投影还需从上述采集结果显式导出并用受控 CLI 手动导入；`sourceAt` 与 `importedAt` 分开，按完整版本事务提交。正式“刷新已导入数据”不执行采集或导入，`complete=false`、`syncMode=manual_import` 不表示持续更新已实现。

原币消费与 USD 账户金额是同笔交易的不同维度；汇总使用来源实际 posted 金额，不再累计 pending 授权。退款保留实际退款金额。财务工作台 USD/USDT 显示两位小数，存储和账本仍保留原精度。

财务 OTC 使用可配置固定报价，默认 1 USDT = 0.99 USD，绑定报价版本。旧 Portal 演示兑换仍有独立的历史费率策略；已改为读取接口报价展示，但尚未统一成 OTC 策略，不能宣称全站使用同一费率。

内部费率方案的 `mg_fees` 继承与独立数字货币沙盒的费用/报价未联动；修改方案不能宣称改变已有 OTC 订单费用。Portal 的历史有效期报价与当前 OTC 固定版本报价也应分开，见 [资金与运营流程](business/funds-and-operations.md)。

### 账户与管理操作

`/customers` 默认列：账户名称、邮件地址、状态、余额、操作。详情分概览、关联卡片、关联交易、数据来源；余额类型和币种分别展示。该目录为来源 Demo，不能当作真实客户资产证明。

后台卡片管理已有隔离Demo冻结、双人审批、扣款及双边资金分录；本地已补独立详情页五个标签、客户解冻申请/退回补充、内部备注隔离与执行限制。真实卡详情读取内部用户绑定及来源投影，尚无受管卡资金映射或上游写能力；未接入操作由后端返回禁用原因。详见 [卡片管理工作台实施记录](frontend/card-management-workspace.md)，其中验证为此前运行证据，本次文档更新不重跑业务测试。

上述五标签详情、客户专用申请和新增执行限制仍需区分规范工作区/旧服务与 GitHub 基线。`/approvals` 提供本地开户审核列表及独立卡操作审批入口；数字货币出金在 `/finance/withdrawals` 审批；`/finance/orders` 是旧 Portal 订单读取入口，不能视为通用资金执行审批中心。

### 内部账本与资金对账（DESIGN）

Slash仅负责上游事实；细分账目、客户归属、卡分户、审批与审计由我们系统负责。独立卡分户不以Slash提供逐卡余额为前提。正式接管前保持原账本权威，本地Demo不自动迁成生产资金。

现有 `/reconciliation` 是来源关联调查，旧前端计算引擎也不能证明完整资金池对平。目标为“资金与财务 → 资金对账”，包括日终核对、客户分户、上游资金池、差异处理。按资产核对内部账、业务账与外部账；有期初、逐笔分录、来源时点和覆盖证据才能下结论。详见 [V1账本与对账规划](domain/reconciliation-v1-plan.md) 和 [R01–R18待执行矩阵](testing/financial-scenarios.md)。

## 本地接口契约增量

以下均属于旧本地服务，默认路径前缀为 `/local-slash-demo/management/`；Portal行单独标注完整路径，均不是Go正式API：

| 接口 | 当前用途 |
| --- | --- |
| GET `live/transactions` | page/pageSize、keyword、status、detailedStatus、cardOnly、cardId、from/to；同一范围后端筛选、分页与汇总 |
| GET `live/overview` | 7/14/30 香港自然日的 USD 资金流、状态、商户和选定卡概览；仅本地已捕获数据 |
| GET `live/transactions/:id` | 交易原值、当前内部用户、cardName/cardLast4 |
| GET `live/cards/:id` | 同连接完整卡或关联卡详情，优先完整卡 |
| GET/POST `card-ownership/cards/:id` | 内部用户绑定、原因、版本、审计；不修改 Slash 或资金权限 |
| GET `card-admin/cards/:id` / GET `card-admin/cards/:id/transactions` | 独立管理详情、动作与禁用原因、按卡筛选交易；source区分Demo/真实投影 |
| POST `/local-slash-demo/portal/action`，type=unfreeze-request | 本地客户端申请/补充资料，绑定冻结版本；不直接解冻上游 |
| GET `live/status` / POST `live/sync` | 手动同步模式与执行进度；无定时上游同步 |
| GET/POST `bins/:id` | 本站产品配置及状态，服务端确认后刷新 |

[字段审计](audits/site-field-api-audit.md) 是前一轮静态/接口快照；其行号和覆盖量不代表本次修改后的全量重新审计。本次验证记录与发布结果分别保存，不将历史记录称为新验收。

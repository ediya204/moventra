## 最新产品决定

### 个人账户与费率

V1 移除面向客户的团队协作入口。底层主体隔离、账户归属及后台内部角色权限保留。独立用户组入口已归并到 `/pricing`；方案维护为 `/pricing/plans` 和 `/pricing/plans/:id`。沿用内部 group_id 及用户覆盖 → 方案默认 → 系统默认的继承关系，不把费率方案当作团队。

### 卡片、用户与 BIN

卡片列表默认展示卡片名称、后四位、来源状态、创建时间、内部所属用户、渠道，操作列放在最后。渠道状态保留原值；未知值明确提示。

所属用户读取内部用户数据库；卡片绑定按命名空间、平台、连接和卡片 ID 隔离。未绑定不从卡名、商户、渠道账户名推断归属。交易展示当前卡片归属，不代表历史交易归属快照或客户资金授权。

卡 BIN 维护详情首屏显示状态区域、影响说明和保存操作。状态包括草稿、上架、暂停、归档，使用既有保存 API 和版本校验；归档不可恢复。已核验的 Slash 产品目录与本地开卡政策分开；真实发卡未接入。

### 卡交易流水

`/transactions?source=slash` 固定查询有来源 cardId 的交易。默认六类来自 detailedStatus：

| 值 | 展示 | 颜色 |
| --- | --- | --- |
| pending | 待入账 | 橙色 |
| settled | 已结算 | 绿色 |
| declined | 已拒绝 | 红色 |
| reversed | 已撤销 | 蓝色 |
| refund | 退款 | 蓝色 |
| dispute | 争议中 | 红色 |

入账状态 status 仍独立保存。其他原始枚举不删除、不转成成功；该页面不提供 ACH 等通用资金分类。卡关联筛选先于分页和汇总；无卡关联的账户收支不混入卡交易。cardId 是关联证据，不据此伪造来源 category。

默认列为商户、卡尾号、原币金额、账户金额、状态、授权时间、入账时间、操作；其他字段通过列选择器查看。列表和“查看详情”打开同一抽屉。抽屉包含商户描述/MCC、单行地区、来源日期、金额、关联卡和内部用户，原始调查字段收进折叠区。

“所属卡片”展示来源卡名与有效四位尾号；按精确来源 ID 打开 `/cards/:cardId?source=slash` 独立详情，旧 `/cards?source=slash&detail=<cardId>` 兼容转入，不使用尾号模糊匹配。固定卡目录外的关联卡可读取独立缓存详情，不加入固定40张卡集合。缺失名称/尾号提示未采集，不用 ID 后缀替代卡号。

### 同步与金额

真实 Slash 同步暂为手动。启动、打开页面、时间流逝均不触发上游请求；界面仅定期读取本地状态。手动关联卡补采为独立只读操作，不改变交易、余额或全量同步成功时间。Webhook 的接收、验签、幂等与乱序处理留待正式接入。

原币消费与 USD 账户金额是同笔交易的不同维度；汇总使用来源实际 posted 金额，不再累计 pending 授权。退款保留实际退款金额。财务工作台 USD/USDT 显示两位小数，存储和账本仍保留原精度。

财务 OTC 使用可配置固定报价，默认 1 USDT = 0.99 USD，绑定报价版本。旧 Portal 演示兑换仍有独立的历史费率策略；已改为读取接口报价展示，但尚未统一成 OTC 策略，不能宣称全站使用同一费率。

### 账户与管理操作

`/customers` 默认列：账户名称、邮件地址、状态、余额、操作。详情分概览、关联卡片、关联交易、数据来源；余额类型和币种分别展示。该目录为来源 Demo，不能当作真实客户资产证明。

后台卡片管理已有隔离Demo冻结、双人审批、扣款及双边资金分录；本地已补独立详情页五个标签、客户解冻申请/退回补充、内部备注隔离与执行限制。真实卡详情读取内部用户绑定及来源投影，尚无受管卡资金映射或上游写能力；未接入操作由后端返回禁用原因。详见 [卡片管理工作台实施记录](frontend/card-management-workspace.md)，其中验证为此前运行证据，本次文档更新不重跑业务测试。

### 内部账本与资金对账（DESIGN）

Slash仅负责上游事实；细分账目、客户归属、卡分户、审批与审计由我们系统负责。独立卡分户不以Slash提供逐卡余额为前提。正式接管前保持原账本权威，本地Demo不自动迁成生产资金。

现有 `/reconciliation` 是来源关联调查，旧前端计算引擎也不能证明完整资金池对平。目标为“资金与财务 → 资金对账”，包括日终核对、客户分户、上游资金池、差异处理。按资产核对内部账、业务账与外部账；有期初、逐笔分录、来源时点和覆盖证据才能下结论。详见 [V1账本与对账规划](domain/reconciliation-v1-plan.md) 和 [R01–R18待执行矩阵](testing/financial-scenarios.md)。

## 本地接口契约增量

以下均属于旧本地服务，默认路径前缀为 `/local-slash-demo/management/`；Portal行单独标注完整路径，均不是Go正式API：

| 接口 | 当前用途 |
| --- | --- |
| GET `live/transactions` | page/pageSize、keyword、status、detailedStatus、cardOnly、cardId；后端筛选分页与汇总 |
| GET `live/transactions/:id` | 交易原值、当前内部用户、cardName/cardLast4 |
| GET `live/cards/:id` | 同连接完整卡或关联卡详情，优先完整卡 |
| GET/POST `card-ownership/cards/:id` | 内部用户绑定、原因、版本、审计；不修改 Slash 或资金权限 |
| GET `card-admin/cards/:id` / GET `card-admin/cards/:id/transactions` | 独立管理详情、动作与禁用原因、按卡筛选交易；source区分Demo/真实投影 |
| POST `/local-slash-demo/portal/action`，type=unfreeze-request | 本地客户端申请/补充资料，绑定冻结版本；不直接解冻上游 |
| GET `live/status` / POST `live/sync` | 手动同步模式与执行进度；无定时上游同步 |
| GET/POST `bins/:id` | 本站产品配置及状态，服务端确认后刷新 |

[字段审计](audits/site-field-api-audit.md) 是前一轮静态/接口快照；其行号和覆盖量不代表本次修改后的全量重新审计。本次验证记录与发布结果分别保存，不将历史记录称为新验收。

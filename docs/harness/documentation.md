# Markdown 状态维护规则

维护日期：2026-09-18。执行者是当前改动的开发者或代理；评审者核对业务政策与验收范围。与代码同一批维护文档，不依赖另一次“整理文档”请求。

## 四类资料

| 类别 | 维护方式 | 例子 |
| --- | --- | --- |
| 现行规则 | 直接修订当前规则，保留决定日期与依据；历史政策另注明失效范围 | AGENTS、DEVELOPMENT、领域规则、UI 规范 |
| 当前指南/状态 | 同步更新正文、路由、命令和能力表，避免只在开头补一句却保留矛盾的“当前”结论 | README、current-state、routes-and-api |
| 设计/候选 | 明确 DESIGN 或本地候选；实施后逐项关联流程、测试与发布证据 | 卡片详情、来源持久化与对账方案 |
| 历史证据 | 保留原日期、版本、命令和结果；后续状态用补充或链接说明，不覆盖过去的事实 | releases、deploy 发布批次、旧审计 |

专题可以包含多类内容，但每节须明确时间和范围。不要仅因文件名较新就覆盖更可靠的证据；代码证明实现，测试报告证明所测范围，发布记录证明对应版本发布，三者不能互相替代。

## 每次变更的更新矩阵

| 变更 | 必须核对的文档 |
| --- | --- |
| 页面、路径或导航 | 子项目 README、routes-and-api、对应 FLOW；同时检查深链与返回 |
| API / DTO / 权限 | 对应专题与机器契约、transport/网关说明、授权与错误语义 |
| 金额或状态 | 领域规则、契约、F/R 场景及相应自动化测试；保持模式区分 |
| 模块新增或能力改变 | current-state 与对应专题；不在每个 README 复制完整能力清单 |
| 运行命令/依赖/迁移检查 | 所属服务 README；基于代码核对，已应用迁移字节保持不变 |
| 发布 | 对应 deploy/releases 记录，精确版本、平台结果、验证限制、回退；再更新 current-state |
| 新增/移动/重命名 Markdown | 人工索引按主题补入口，运行 docs:index 与 docs:check |
| 仅文字或链接修复 | 修正文档并运行 docs:check；不更新业务测试日期或声称重新上线 |

“保持最新”表示完成每批变更时同步维护，不代表已配置持续监控或定时访问生产。没有新证据，不把历史平台版本写成已实时复验；日期更新也不等于内容已验证。

## 状态记录最小字段

需要描述实现/发布状态时记录：核对日期、源码提交及相关未提交增量、作用环境、设计/实现/自动化/浏览器/真实渠道/部署分别的结果、证据链接、尚未完成项。UNKNOWN 写“待验证”，不自动填“通过”；不适用说明理由。

当前状态以 [current-state](../current-state.md) 汇总，最新细节以对应专题及证据为依据。历史快照保持链接可达；移动文件时修正相对路径和引用，不丢弃原记录。

## 自动检查与人工复核

- `pnpm docs:index` 只生成 docs/catalog.md 的文件清单，不修改业务状态或更新时间。
- `pnpm docs:check` 检查仓库自有 Markdown 的本地链接文件、标记为 json 的围栏示例，以及完整目录是否与文件一致。目录覆盖根目录、docs、deploy、apps、services、packages；排除依赖、构建、隐藏目录及第三方 minimals 源目录。
- 自动检查不验证外链在线状态、Markdown 标题锚点、金额业务语义、运行能力或云端版本。通过后仍需人工对照本次代码和证据核对“已实现/已部署”描述。
- 本地链接断开、无效 JSON 或目录过期返回非零状态。新增文档后先生成目录；不要通过删除历史证据绕过检查。

未引入 CI、Git hook、自动发布或文档监控服务。后续可在用户采用的流水线运行相同检查命令，不改变提交权限和生产边界。

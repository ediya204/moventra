# 卡片详情入口修复

日期：2026-09-07。范围：本地 8850 运营后台预览，以及正式后台的关联卡片跳转。

## 原因与行为

8850 运行于旧版预览工作区，卡片列表“详情”和交易抽屉“所属卡片”仍打开旧弹窗，未接入主工作区已有的独立卡片详情页。

两个入口现统一导航到 `/cards/:id?source=slash`，使用选中卡片或交易关联卡片的来源 ID。详情展示沿用现有卡片工作台，不改变交易与余额口径。

## 本地实现

- 将主工作区已有的卡片工作台及商户展示依赖同步到运行中的预览工作区。
- 两个入口改为独立页面导航；保留全部卡片中的可用余额列。
- 前端本地请求白名单增加卡片范围内交易查询 GET，服务端继续执行原有资源授权。
- 未改变 Slash 上游接口、同步逻辑、资金权限或余额；真实卡片继续按只读接入边界展示。

## 本次验证与交付边界

- 预览工作区 `pnpm --filter @moventra/admin typecheck` 通过。
- `node --test tests/frontend/transaction-drawer.test.mjs`：5 项通过。
- 浏览器实际点击卡片列表“详情”，成功进入对应卡片独立详情页。
- 浏览器实际点击交易抽屉“所属卡片”，成功进入对应卡片独立详情页。
- 关联卡片详情的“交易流水”标签加载成功，展示 1 条记录。

以上为此前本地修复验证。后续用户授权同步、部署；发布结果见下方记录。

## 正式后台兼容修复

正式后台使用独立只读渠道页面，详情地址为 `/cards/:id?connection=...`。原交易抽屉使用整页导航，会重新初始化仅在内存中保存的 Firebase 会话。现改为 React Router 站内导航，保留渠道连接参数；列表卡片链接编码卡片及连接 ID。

生产不加载本地 Demo 卡管理工作台，也不开放本地“全部卡片”列表。此次同步该工作台的源码及可用余额列，不等于将本地 Node 接口或资金能力上线。正式卡资料仍使用已部署的授权 Go 查询，API、数据库及认证权限不变。

发布结果见 [本次发布记录](../../deploy/2026-09-07-card-detail-navigation.md)。

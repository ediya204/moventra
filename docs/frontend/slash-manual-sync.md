# Slash 本地手动同步

更新日期：2026-09-07。此规则取代历史文档中的5分钟自动更新。GitHub 保存前端，旧本地 Node/Python 执行服务与缓存未迁入仓库，正式 Go 没有同名端点。

## 触发与状态

只有运营点击“手动同步”或明确运行手动补采命令才发起上游GET。打开页面、服务启动、时间流逝、同步成功或失败均不安排下一次上游请求。前端每15秒读取本地进度，不等同于采集。

`live/status` 返回 syncMode=manual、webhookConnected=false、nextAt=null、intervalSeconds=null、workerRunning=false。页面展示最近成功时间、覆盖范围、失败和数据待更新提示；workerRunning=false在手动模式不表示故障。

固定卡目录与交易关联卡独立：常规同步更新固定选择及有限范围交易；手动关联卡补采仅补卡资料，不重算余额、不改固定选择、不更新全量同步成功时间。记录独立采集时间和审计。

## 保留约束

连接授权、来源范围、并发合并、超时和失败保留旧数据继续生效。只读请求白名单明确排除PAN/CVV和金融写操作。没有自动绑定内部用户、创建账本或发布金融命令。

## 后续 Webhook

当前未部署接收端、事件订阅或回调。后续需独立接入原始请求体验签、eventId去重、乱序/重放控制及缺失通知补同步；来源事件时间、对象更新时间与本系统采集时间分开。官方依据：[Webhook Overview](https://docs.slash.com/api-reference/webhook-overview)。

本次会话测试已验证启动与时间流逝不触发采集、手动并发合并及失败不自动重试。补采结果仅证明本地只读资料更新，不代表Webhook或真实资金操作验收。

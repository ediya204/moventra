# 客户卡片中心：列表与三级详情

## 页面结构

1. `/portal/cards`：列表、条件查询、排序、分页、选择与导出。
2. `/portal/cards/:cardId`：单卡概览、交易记录、资金记录、操作记录。
3. `/portal/cards/:cardId/records/:recordId`：该卡的交易/操作详情，或嵌入的资金订单详情。记录必须属于当前卡片，否则显示未找到。

单卡发起资金转回后直接进入本卡下的三级订单详情。资金状态、时间线和演示控制区复用资金中心组件，避免两套订单状态逻辑。

## 列表与查询

- 默认按开卡日期倒序；可按卡名、余额、日期切换排序。
- 查询卡片名称、尾号/编号、项目，支持归属子账户。
- 状态分栏：全部、使用中、自助冻结、风控冻结。分栏数量基于当前其他查询条件。
- 更多条件：投放平台、余额上下限、开卡日期范围。
- 低余额快捷条件：小于 200 USD；这是演示阈值。
- 生效条件显示标签，可逐项删除或清除全部；无结果显示操作指引，非法余额/日期范围显示错误。
- 分页支持 10/20/50 条；超出结果范围时钳制到最后有效页。
- 支持选择本页、多页累积选择、导出选择或全部匹配结果。变更查询条件清空选择；下钻后也清空选择。
- 表格展示名称及尾号、子账户、状态、平台/项目、可用余额、开卡日期和操作。

金额均为 USD。现有种子卡增加合成的平台/项目和开卡日期；新建演示卡默认未分类，不推断真实平台数据。

## 下钻体验

筛选、排序、页码与二级分栏、记录查询参数保存在 URL。面包屑和返回按钮保留这些参数。浏览器前进后退亦可还原查询条件。刷新仍会重置演示业务数据，因此刷新后新建卡或订单可能显示未找到；URL 中的条件不丢失。

单卡页的交易、资金、操作记录可按名称/编号、状态和类型继续筛选，每页 10 条。三级详情返回后保留记录筛选与页码。

- 交易：消费与退款，展示金额、商户、时间和结果；失败示例明确不代表实际扣款。
- 资金：卡片充值、资金转回，展示订单与资金处理时间线。
- 操作：开卡、冻结、解冻，展示操作事件；不把零金额操作当成资金流水。

## 操作与响应式

列表行只保留详情与更多操作，更多菜单内提供充值、转回、冻结/解冻或风控处理申请。单卡页提供明确的主要操作栏。单卡操作表单限制在当前卡片，防止上下文误选。

冻结/解冻前显示卡名和尾号确认；风控冻结无法自行解除。选择导出不会触发批量金融操作。

移动端筛选纵向排列，表格在自身容器内横向滚动，固定选择列和名称列，保留完整字段与操作入口；页面本身不横向溢出。

## 验证

- `pnpm run build`
- `node --test tests/portal-cards.test.mjs tests/portal-model.test.mjs tests/portal-finance.test.mjs`
- 浏览器验证尾号查询、一级到二级到三级再返回时保留查询、单卡转回跳到嵌入资金详情，以及桌面/移动端布局。

这些功能仍使用本地合成数据。正式上线需要客户专用服务端分页查询、组织与卡片授权、真实卡元数据、操作审计与渠道能力支持。

单卡概览新增 CVV 临时展示区域。演示卡仍只显示掩码；远程获取合同与清除策略见 [CVV 说明](./client-cvv.md)。

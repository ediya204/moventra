# 卡交易状态分类与视觉规范

更新日期：2026-09-07。来源依据：[Slash Transaction](https://docs.slash.com/api-reference/schema-transaction)。适用于 `/transactions?source=slash`；通用状态展示组件仍兼容 Demo 与旧记录。

## 卡消费范围

默认筛选只提供六类 detailedStatus：pending（待入账）、settled（已结算）、declined（已拒绝）、reversed（已撤销）、refund（退款）、dispute（争议中）。移除 ACH 退回、通用资金审批等选项。其他原始枚举保存在数据及详情中；缺失和未知不改成成功。

页面固定传 cardOnly=true。旧本地 API 先限制非空字符串 cardId，再按关键词/状态筛选、分页和汇总；无卡关联的账户收支不进入此页。该规则只依据明确卡关联，不伪造 category 字段。

## 两层状态与查询

status 是 pending/posted/failed 的入账维度；detailedStatus 提供拒绝、撤销、退款等分类，两者独立保存。默认状态列采用详细分类，提示中保留原始值；金额汇总仍依据 status=posted，不因颜色或菜单分类改变。

本地查询新增详细状态参数 detailedStatus，使用参数绑定精确匹配；总行数、分页和汇总共用筛选条件。旧status参数保持兼容，以可删除标签提示。选择新分类清除旧status条件并回到第一页；未知来源枚举可按原值查询。

## 系统组件样式

MUI Chip 使用文字、图标和浅色底：待入账橙色，结算绿色，拒绝/争议红色，撤销/退款蓝色；未知与缺失中性显示。拒绝等异常行突出红色，待入账采用次级文字色，撤销行商户/卡片/金额加删除线。状态与操作保持可读和可点击。

不缓存历史状态颜色；每次根据最新接口响应计算。退款尚未入账、异常状态组合与未知枚举不能按已结算处理。菜单中的退款是分类，具体行仍显示实际处理状态。

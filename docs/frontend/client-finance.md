# 客户资金中心：USDT 充值、兑换与提现

## 本轮实现

入口 `/portal/funds`，七个标签页：资产总览、USDT 充值、兑换、提现、内部划拨、收款地址、资金流水。与管理后台认证和 `/admin-api` 隔离，不触发任何真实金融操作。模型和本次会话数据保存在内存，刷新或退出重置。

- USDT 与 USD 可用余额、冻结/预占分别展示。卡片、子账户、卡片转回处理中分别核算，未入账充值不算资产。
- 充值页提供不可收款的 DEMO 标识、对应二维码、复制功能与演示网络选择，接受最多六位小数的预期金额。
- USDT ↔ USD 手动报价兑换，60 秒倒计时，显示方向、总支付、内含费用和净到账。过期需重新确认，不能重复使用报价。
- 提现先选择演示地址，再核对网络、到账数量、另扣费用、总扣款及剩余余额；演示勾选不代表真正二次身份验证。
- 地址簿新增、重复检查、启用/停用；仅接受 `DEMO:TRON:…`，不接受真实钱包地址。既有订单保存提交时地址快照。
- 主账户与子账户同币种划拨；充值到卡可选主账户或所选卡所属子账户。卡片转回通过模拟渠道结果确认。
- 资金订单按类型、币种、日期与关键字筛选，CSV 导出，订单详情包含时间线、关联卡片、地址、报价或模拟交易标识。交易总表支持混合币种显示并跳转资金订单。
- 对应资金结果产生消息；订单详情的客服入口携带订单编号。

## 演示参数（不是真实报价或渠道规则）

| 参数 | 演示值 |
|---|---|
| 初始主账户 | 5,000 USDT / 28,450 USD |
| 网络 | TRON · TRC20（演示）；不代表真实渠道已开通 |
| 充值地址 | DEMO:USDT:TRON:DO-NOT-SEND，不能接收任何资产 |
| 最低充值 | 10 USDT，演示充值费 0 |
| 兑换方向及汇率 | 1 USDT → 0.997 USD；1 USD → 1.001 USDT |
| 兑换费 | 支付币种金额的 0.5%，包含在支付总额内 |
| 报价有效期 | 60 秒 |
| 提现范围 | 单笔 10–100,000 USDT |
| 提现费用 | 另扣 2 USDT，收款数量为客户填写数量 |
| 卡充值 / 转回 / 内部划拨费用 | 演示为 0 USD |

USD 使用整数美分，USDT 使用整数微单位。报价换算用 BigInt 整数中间计算，手续费向上取整、到账向下取整；不默认 1:1，不混币种累计金额。

## 状态与资金

- 充值：待检测 → 确认中 → 已完成；可先进入需核查。仅完成时增加 USDT，完成后不可再次入账。
- 兑换：确认报价预占支付资产 → 处理中 / 待核实 → 完成增加收款资产，失败退回支付资产。超时不释放。
- 提现：申请即预占数量与费用 → 待审核（可取消或拒绝） → 处理中（不可取消） → 完成 / 待核实 / 已确认失败。取消、拒绝、确认失败释放资金；完成最终扣除。审核通过不等于转账成功。
- 卡片转回：从卡可用余额扣除，计入转回处理中；成功计入主账户，失败恢复原卡余额。冻结卡不可发起。
- 内部划拨和模拟充值到卡：即时完成，所有资金位置之和守恒。

订单详情底部有折叠的 **演示控制区**。这里模拟检测到账、需核查、入账、审核、最终成功/失败和超时结果；正式客户页面不能提供这些控制。重复事件 ID 不重复处理，不允许已终结订单再次成功或释放资金。

## 手动验收路径

1. 进入客户演示，资金中心 → USDT 充值，输入 `100.000001`，创建订单。
2. 展开演示控制区，模拟检测到账、确认入账。USDT 从 5,000 增加至 5,100.000001。
3. 兑换 100 USDT，确认报价：其中费 0.5 USDT、净得 99.20 USD。模拟成功后 USD 增至 28,549.20。
4. 地址簿添加 `DEMO:TRON:treasury`，提现 100 USDT，显示总扣款 102 USDT。勾选演示确认后提交。
5. 模拟审核通过后取消按钮消失；模拟超时进入待核实；最终成功后结束订单，预占释放到结算而非可用余额。USDT 可用余额为 4,898.000001。
6. 卡片中心 → 转回账户，提交后查看在途金额；模拟成功才增加 USD。

## 验证与后端边界

运行 `pnpm run build` 和 `node --test tests/portal-model.test.mjs tests/portal-finance.test.mjs`。

自动化覆盖金额精度、到账重复事件、过期报价、余额不足、预占释放、冻结卡、待审核取消、审核与最终结果分离、转回及子账户/卡片余额守恒。浏览器已验证上面的充值、兑换、提现流程，以及 390px 视口下订单详情无页面横向溢出。

上线仍需客户身份与组织权限、真实二次验证、地址链格式校验、开户/服务门禁、限额与费率配置、真实钱包和渠道接入、服务端报价签发、持久化订单与幂等原子账务、回调验签、防重复链上事件、对账及业务验收。实际充值应根据链上已确认的真实金额入账，不能使用客户填写的预期金额。真实转回额度必须排除预授权和未结算金额。本次没有接入这些能力，也未部署上线。

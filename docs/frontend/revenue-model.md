# 收入确认与分析模型

## 当前仓库状态（2026-09-07）

收入分析为运营 Demo 模型，生产无收入事件或聚合 API。历史 number 金额、单一来源 ID 和跨币种合计不能直接用于正式账务；新实现需最小单位字符串、来源范围键和明确币种口径。

本页为历史设计/实现档案。下方的“当前”“已实现”“本次”均指原记录当时；历史端口、脚本、迁移、数据及测试结果不代表现有仓库可复现或生产已验收。当前能力与可执行命令见 [文档索引](../README.md)、[开发总纲](../DEVELOPMENT.md)。

## 历史记录正文

## 当前收入范围

当前只纳入两个收入项目：

1. OTC 手续费；
2. 开卡费。

返佣明确排除。交易本金、充值、入金、出金、授信额度、用户余额、渠道余额和退款本金都不是收入。

## 收入确认

```text
已确认收入 = sum(status = recognized 的 OTC 手续费和开卡费)
```

- `pending`：待确认，单独展示，不进入已确认收入；
- `recognized`：已确认，进入收入；
- `reversed`：已冲回，保留历史证据，不进入当前已确认收入。

不能根据“订单已创建”或“资金已流入”直接确认收入。生产环境应以会计认可的收费完成状态为准。

## 标准收入事件

```ts
type RevenueEvent = {
  id: string;
  revenueType: 'otc_fee' | 'card_issuance_fee';
  userId: string;
  amount: number;
  currency: string;
  status: 'pending' | 'recognized' | 'reversed';
  occurredAt: number;
  recognizedAt?: number;
  sourceRef: string;
  cardId?: string;
};
```

每个事件必须有不可变 ID 和来源单号。OTC 手续费回到 OTC 订单，开卡费回到开卡记录。

## 核心指标

- 已确认收入：两类已确认事件合计；
- OTC 手续费收入；
- 开卡费收入；
- 待确认收入：观察未来可能确认但当前不能计入的金额；
- 已冲回金额：观察收入质量，不与待确认混合；
- OTC 手续费率：OTC 已确认手续费 / 对应 OTC 账面交易量；
- 平均开卡费：已确认开卡费 / 已确认开卡收费事件数；
- 账户收入集中度 HHI：每个账户收入占比平方和。

OTC 手续费率必须使用与手续费同范围、同币种、同截止时间的交易量。当前 Demo 使用用户资金报表中的 OTC 转法币和转币金额作为账面分母。

## 时间口径

- 趋势按收入发生时间 `occurredAt`；
- 已确认收入以确认状态为准；
- 发生时间和确认时间跨周期时，生产会计报表应按财务政策选择权责发生或收付实现口径，运营后台不得自行混用；
- 7/30/90/180 日筛选只在存在逐笔事件时准确。只有账户汇总时，页面必须标记“账户汇总”，不能伪造逐日趋势。

## 汇总核对

```text
选择范围收入 = OTC手续费 + 开卡费
汇总差异 = 选择范围收入 - 旧资金报表毛收入
```

如果旧毛收入还包含其他项目，页面会显示差异，要求确认旧接口口径，不会自动把未知差额分摊到两类收入。

## 数据质量

页面记录：

- 逐笔或账户汇总粒度；
- 发生时间覆盖率；
- 状态覆盖率；
- 账户归属覆盖率；
- 重复收入事件 ID 数；
- 模型版本。

未来增加返佣时，必须新增独立 `revenueType`、确认条件、冲回事件和来源单号，并经过明确产品确认后再进入收入合计。

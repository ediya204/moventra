# 卡交易详情抽屉与关联卡

更新日期：2026-09-07。适用于本地 Slash 只读页面；GitHub 保存前端实现，Node/Python 查询服务位于旧工作区。正式 Go 未接入这些详情接口。

## 查询与页面

`/transactions` 的整行点击和“查看详情”打开同一 MUI Drawer，读取 `management/live/transactions/:id`。加载、失败重试、关闭与切换记录均有处理；过期响应不能覆盖当前选择。

顶部展示商户、账户金额、来源日期、UTC/本地时区和状态。详情包括交易 ID、关联卡、内部所属用户、授权时间、入账时间、商户描述/MCC、单行地区及原币金额。来源标识与同步信息收进折叠区。附件与备注未接入时明确提示，不提供假上传或地图。

status 与 detailedStatus 保留；仅 posted 从 date 显示入账时间。pending 金额不作为最终清算金额。未知、零值和缺失分别处理。

## 卡片关联

“所属卡片”显示 `卡片名称 · •••• 后四位`，例如合成展示 `Demo Card · •••• 0012`。卡名来自 Slash name，后四位来自 last4；不把 ID 后缀当卡号。所属用户来自内部数据库，与卡名无关。

交易接口在当前连接范围关联 `card` / `card-reference`，返回 cardName/cardLast4。补读详情必须与当前交易 cardId 一致；其他卡的迟到数据不能作为该卡标签。缺失资料明确显示未采集。

跳转 `/cards?source=slash&detail=<cardId>`，使用精确 ID 读取同连接详情，不通过名称或尾号模糊匹配。关联卡可以不在固定40张卡的目录内；读取关联缓存不会将其加入目录。卡片与交易切换时重建目录状态，避免遗留搜索条件。

## 本地补采

旧本地 `adsflow-api/scripts/slash_live.py` 支持 `enrich-references --limit 200`。仅显式手动执行，使用受限 GET 及白名单投影，补齐卡名、后四位、状态和产品/账户关联；不获取PAN/CVV，不更新交易、余额或全量同步成功时间。运行记录写入本地采集审计。此脚本不在当前 GitHub 仓库，不能直接在仓库根目录执行。

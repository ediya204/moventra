## 历史记录正文

入口：`http://127.0.0.1:8850/portal/messages`，隔离 Demo 前端也可使用 8852 端口。

## 页面与交互

- MUI 表格展示主题、类型、消息时间和末尾操作列，未读消息使用蓝色提示与加粗主题。
- 全部 / 未读 / 已读分栏；搜索主题、正文、卡片与订单编号；按卡片、资金、系统筛选；分页与新旧顺序切换。顺序依据现有消息入库顺序，不将未知时间当作当前时间。
- 单条、批量与全部标为已读；选定消息可以恢复未读。批量选择只作用于本页。
- 点击行或主题进入 `/portal/messages/:id`，桌面右侧显示完整详情，窄屏切换为单列详情；返回保留筛选条件。
- 已核实关联的消息提供卡片 / 资金订单入口，不根据模糊正文猜测业务关系。
- 加载、失败重试、空结果和无未读消息都有明确反馈。

## 数据与接口

复用 `portal_state.state_json.notices`，新增可选 `title/category/createdAt/cardId/orderId`，不做破坏性迁移，不清空旧消息。新业务动作写入消息元数据，已有消息原文不覆盖。少数旧通知通过同 ID 交易、明确订单通知格式或原有固定种子记录映射恢复关联；没有证据的时间显示“—”，详情解释缺失原因。

- GET `/local-slash-demo/portal/messages`：后端查询、分页、筛选和计数。
- GET `/local-slash-demo/portal/messages/:id`：独立详情，不依赖当前列表页。
- POST 原有 `/local-slash-demo/portal/action`，`{type:"read", ids?:string[], read?:boolean}`：复用持久化事务、版本校验和幂等保护。省略 ids 表示全部标为已读；恢复未读必须传入 IDs。无效或不属于当前工作空间的 ID 整笔拒绝。

两端共享 `messageQuery.ts` 的白名单映射。侧栏未读数使用动作响应中的状态更新。查询在后端执行，但存储仍沿用本地 JSON 快照；尚未将消息拆为生产规模的独立表，也未新增跨标签实时推送。其他标签修改造成版本冲突时，会重新读取状态并提示重试。

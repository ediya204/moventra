## 后续开发默认规则

## 确有新失败时的排查顺序

1. 先区分错误层：Slash 上游 IP 白名单、应用登录邮箱准入、前端/网关路由白名单和数据库网络访问不是同一个问题。不能只凭 HTTP 403 判断是 Slash IP 白名单。
2. 对照已有成功调用，确认调用方是本地服务、MCP 还是云端服务，并核对连接、凭据配置来源及出口是否一致。复用已配置环境；不猜 IP、不打印密钥、不直接放宽白名单。
3. 当前任务已授权真实只读验证时，仅在对应环境执行一次最小、已批准 GET，记录时间、调用环境、脱敏连接标识、HTTP 状态、上游错误码/请求标识。没有调用则明确记为未复验，不因此阻止文档或隔离实现工作。
4. 如新请求仍返回上游白名单错误，只报告该环境的新失败；停止该连接重复请求，再定位配置差异。现有 401/403 暂停机制保留，用户说明问题解决不意味着忽略新的运行错误。
5. 连通成功后追加环境及证据，分别记录业务数据覆盖、Webhook 和资金验收；网络放行本身不代表这些验收通过。
